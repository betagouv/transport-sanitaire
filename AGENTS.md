# AGENTS.md

## Présentation

Le dépôt public du simulateur d'éligibilité au transport sanitaire et de ses
outils. C'est un monorepo en workspace pnpm : une seule installation, à la
racine, et un seul `pnpm-lock.yaml`. Le toolchain (Node, pnpm, `gh`) vient de
`mise`, déclaré dans [`mise.toml`](mise.toml).

## Commandes

| Commande | Ce qu'elle fait |
|---|---|
| `pnpm verifier` | passe le `verifier` de chaque app, l'une après l'autre |
| `pnpm --filter <app> <script>` | lance une action d'une app, par exemple `pnpm --filter simulateur-eligibilite dev` |
| `pnpm --filter <app> verifier` | vérifie une app : lint, typecheck, knip, tests, build, selon l'app |
| `pnpm agents` | régénère les quatre `AGENTS.md` depuis leurs sources (ADR-0011) |
| `pnpm audit` | audite les dépendances du lock unique |
| `tsp` | prépare la machine, ouvre les outils, tire une branche, ouvre la PR : voir [`apps/cli`](apps/cli/README.md) |

La CI et le `Procfile` appellent `pnpm`, jamais `tsp` : la production ne dépend
pas de la CLI. Ce qu'on lance avant de pousser, et pourquoi, est dans
[`travailler-dans-le-depot.md`](docs/knowledge/contributing/travailler-dans-le-depot.md).

## Commandes de tsp

| Commande | Ce qu'elle fait |
|---|---|
| `tsp setup` | prépare la machine |
| `tsp doctor` | dit ce qui manque, et la commande qui le répare |
| `tsp open` | liste les outils du projet |
| `tsp open <outil> […]` | ouvre un ou plusieurs outils dans le navigateur |
| `tsp branch <type>/<sujet>` | tire une branche de `staging` |
| `tsp pr` | pousse la branche et ouvre la PR vers `staging` |

`tsp help` affiche cette liste. `doctor` et `open` acceptent `--json`.

**Le reste n'est plus dans `tsp`.** Une commande retirée répond par ce qui la
remplace.

| Besoin | Geste |
|---|---|
| lancer une action d'une app | `pnpm --filter <app> <script>`, par exemple `pnpm --filter simulateur-eligibilite dev` |
| vérifier une app | `pnpm --filter <app> verifier` |
| lire les règles, les skills, la doc | ouvrir les fichiers : `docs/knowledge/contributing/`, `.claude/skills/`, `docs/knowledge/` |
| état d'une PR et de sa CI | `gh pr view`, `gh pr checks` |
| suivre un chantier | son ticket Notion, tenu à la main |

## Skills

- `implement-publicodes-version` (`.claude/skills/implement-publicodes-version/SKILL.md`) : Intégrer une nouvelle version du modèle d'éligibilité livrée par l'éditeur dans apps/simulateur-eligibilite (paquet déposé dans tmp/<version>/package/). À charger dès qu'il s'agit de recopier, porter ou monter le modèle publicodes, de faire le diff d'un livrable, ou de remonter une anomalie à l'éditeur.
- `livrer-une-version` (`.claude/skills/livrer-une-version/SKILL.md`) : Livrer une version d'une app : numéro, entrée de CHANGELOG, montée du package.json par une PR vers staging, tag `<app>@<version>`, release GitHub, puis fusion de staging dans main. À charger dès qu'il s'agit de livrer, publier, étiqueter ou « sortir une version ».
- `revue-d-une-pr` (`.claude/skills/revue-d-une-pr/SKILL.md`) : Faire la revue d'une PR et de son ticket Notion, fonctionnelle puis technique. Elle donne le contexte, un tl;dr, les écarts au ticket, ce que les tests couvrent, un cahier de tests à cocher, un verdict, et lance l'app en local pour tester. À charger dès qu'on demande de revoir, relire ou recetter une PR ou une branche.
